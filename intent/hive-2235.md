## Problem

Every new claude agent pane can freeze on Claude Code's interactive prompt "New MCP server found in this project: graft … Use this MCP server / Continue without using this MCP server". Seen 2026-09-15 on hive task 453e27cabbaa: hive raised decision dec_7f424c4ee62d ("Agent blocked on a dialog") and the director had to answer "deny" by hand. Cause: the director's global Claude settings run @nanonets/graft's SessionStart hook (`~/.claude/helpers/graft-hooks.cjs session-start`), which indexes the cwd (a `graft/` dir appeared in the agent worktree) and registers a project-scoped MCP server (`dist/hosts/mcp-config.js` writes `.mcp.json`); Claude Code then asks before enabling a project MCP server. Agents never need MCP servers, and each spawn is a fresh worktree, so this repeats per task.

## Fix

When hive spawns a `claude` agent (api.ts around agentForConfig / the herdr spawn that calls writeHookSettings), pass `--strict-mcp-config` together with an empty `--mcp-config` (inline JSON `{"mcpServers":{}}`), so project and user MCP configurations are ignored and the prompt cannot appear. Keep codex argv unchanged. Also set `"enableAllProjectMcpServers": false` is NOT enough on its own (the prompt is per-project); the flags are the fix. Make it configurable per project (`config.agent_mcp: "none" | "inherit"`, default `none`) so a project that genuinely wants MCP tools for agents can opt in.

## Check that must pass

A unit test on the argv builder asserting the two flags for claude and their absence for codex; `bun test` green; one real spawn on the live checkout of a throwaway chore whose worktree contains a `.mcp.json` with a dummy server, showing the pane reaches the first tool call with no MCP dialog (attach the pane log).
