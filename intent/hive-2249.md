## Problem
# Codex protocol driver: `codex exec --json` subprocess per task, no pane

## Why
Claude workers run on the protocol driver (server/src/runtime/claudeStream.ts, `ClaudeStreamRuntime`) since 2026-09-16 and all three projects are flipped. Codex is the last agent that still needs a tmux pane (server/src/api.ts `agentForConfig` -> herdr pane path). Give codex the same shape so the pane runtime can be deleted afterwards.

## Verified facts (2026-09-17, codex-cli 0.149.1)
- `codex exec --json "<prompt>"` prints JSON lines on stdout: `{"type":"thread.started","thread_id":"..."}`, `{"type":"turn.started"}`, `{"type":"item.completed","item":{...}}`, then `{"type":"turn.completed"}` or `{"type":"turn.failed","error":{...}}`. Stdin is read once as extra prompt, it is NOT a live message channel.
- Steers therefore go through a new turn: `codex exec resume <thread_id> --json "<steer text>"` (see `codex exec resume --help`). One subprocess per turn, same thread id across turns.
- `codex exec` accepts the same `-c` overrides and `--sandbox`/`--ask-for-approval` flags that `codexAgentArgv` (server/src/api.ts, grep `export function codexAgentArgv`) already builds for the pane path, including the hive hook overrides (`codexHookOverride`). Reuse that argv builder, only swap the leading `codex` for `codex exec --json` and drop nothing else.
- `codex exec` on this machine currently fails every turn with "The 'gpt-6-astra' model requires a newer version of Codex" (CLI too old for the account default). Upgrading codex is a director/host step, not yours. Build against the event shape above with a fake `SpawnProc`, exactly as server/test/claudeStream.test.ts does.

## Change
1. New file server/src/runtime/codexStream.ts exporting `CodexStreamRuntime` with the same public surface as `ClaudeStreamRuntime` (grep `class ClaudeStreamRuntime` for the method list: spawn, send, wait, probe, read, close, has, list, sessionId, goneByCwd). Status vocabulary identical: `working` from turn.started until turn.completed/turn.failed, then `idle`; `gone` once no turn is running and close() was called or the last process exited non-zero without a thread id.
   - spawn: run argv from `codexAgentArgv(...)` with `exec --json` inserted after `codex`, cwd = worktree, env as given. Capture `thread_id` from thread.started.
   - send(text): spawn `codex exec resume <thread_id> --json <text>` with the same `-c` overrides, cwd and env. Queue sends while a turn is running; deliver when it goes idle.
   - Transcript and per-task jsonl log exactly like claudeStream (`TRANSCRIPT_MAX`, `appendFileSync` to the same log dir).
2. server/src/runtime/herdr.ts: the `driver === "protocol"` branch (grep `if (args.driver === "protocol")`) and every `this.stream.has(target)` short-circuit must pick the runtime by agent: keep one map of task id -> runtime (claude or codex). Smallest diff: give `Herdr` a second field `codexStream` and a private `streamFor(target)` helper, then replace the `this.stream.has(...)`/`this.stream.xxx(...)` pairs with `streamFor`. Do not touch the pane branches.
3. server/src/api.ts driver selection (grep `driver: agent === "claude" && config.agent_driver === "protocol"`): drop the `agent === "claude"` condition so codex projects on `agent_driver: "protocol"` use the new runtime. Pass `agent` down in SpawnArgs.
4. `spawned` event payload must keep `tab_id: null` for both protocol runtimes (the smoke check reads it).
