## Problem
# Stop agents committing graft's `.ignore` from the seeded worktree

## Why
Every worktree hive seeds gets `graft build` run in it (server/src/api.ts, grep `["graft", "build"]` near `graft/INDEX.md`). graft writes a repo-root `.ignore` (ripgrep config re-admitting graft/ to search). That file is absent from origin/main on both corebeat and hive, so agents `git add -A` it and the risk check then blocks the PR as scope creep. Seen 2026-09-17 on corebeat PRs #1369 and #1368 (task 2241 needed a manual fix commit); it also shows up in older "WIP rescued" commits.

## Change
In the same `prepareWorktree` step that runs `graft build`, make `.ignore` invisible to git for that worktree without touching tracked files: append `.ignore` to the exclude file git resolves for the worktree (`git -C <worktree> rev-parse --git-path info/exclude`, create the file if missing, skip if the line is already there). Do it right after the graft build, only when `.ignore` exists and `git -C <worktree> ls-files --error-unmatch .ignore` fails (i.e. the repo does not track it). One helper, called from that one place.

## Check that must pass
- A test in server/test that seeds a scratch git repo under the scratchpad (never a default path), runs the helper, and asserts `git status --porcelain` no longer lists `.ignore` while a tracked `.ignore` in another scratch repo is left alone.
- `bun run typecheck` and `bun test server/test` green.
- One real spawn on the hive project after the change: attach `git -C <worktree> status --porcelain` from the new worktree showing no `.ignore`.
